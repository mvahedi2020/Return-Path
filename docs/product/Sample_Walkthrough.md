## Meaningful mistake and recovery

After a run, **Review sample reset** says how many runs and policy versions will be cleared. Cancel leaves them intact. Confirm clears the whole fictional scenario. **Undo sample reset** restores the exact compatible prior timeline once. The next accepted run/revision/reset or refresh expires Undo. Another saved change also expires Undo rather than overwriting it.

An incompatible saved sample displays a preservation notice and disables run/policy acceptance. Reset preview explains that corrupt bytes have no Undo. Cancellation preserves those bytes; only a fresh confirmed reset replaces the reviewed value. If the bytes change while the preview is open, confirmation expires and a new review is required.

When storage cannot be read, the timeline still works in memory and clearly warns that unseen bytes are preserved. A working write method cannot bypass that rule. A write failure warns that refresh may lose the memory change. Compatible refresh restores policy/run snapshots and their explanations.
